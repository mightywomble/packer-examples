HashiCorp requires `communicator = "winrm"` explicitly for Windows builds and explains that a brand-new Windows ISO generally needs WinRM bootstrap configuration supplied through `Autounattend.xml`. [developer....hicorp.com]
Important limitation
An `Autounattend.xml` for Windows 11 ARM64 is not reliably universal. Its edition index, locale, disk layout, account setup and driver-loading paths must match:

-   your exact ISO;
-   your ISO language;
-   Windows edition;
-   QEMU devices;
-   VirtIO media layout.

Do not blindly reuse an x64 answer file.

Step 9: Test before Sysprep
Example `scripts/40-validate-image.ps1`:
PowerShell
$ErrorActionPreference = 'Stop'

$results = [ordered]@{
TimestampUtc = (Get-Date).ToUniversalTime().ToString('o')
Architecture = $env:PROCESSOR_ARCHITECTURE
SevenZipInstalled = Test-Path 'C:\Program Files\7-Zip\7z.exe'
PowerShellSevenInstalled = Test-Path 'C:\Program Files\PowerShell\7\pwsh.exe'
OpenSshServerInstalled = (
Get-WindowsCapability -Online -Name 'OpenSSH.Server~~~~0.0.1.0'
).State -eq 'Installed'
ScriptBlockLogging = $false
SmbV1Disabled = $false
GuestDisabled = $false
}

$scriptLoggingPath =
'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging'

if (Test-Path $scriptLoggingPath) {
$results.ScriptBlockLogging =
(Get-ItemProperty $scriptLoggingPath).EnableScriptBlockLogging -eq 1
}

$smbState = Get-WindowsOptionalFeature `
-Online `
-FeatureName SMB1Protocol `
-ErrorAction SilentlyContinue

$results.SmbV1Disabled = $smbState.State -ne 'Enabled'

$guest = Get-LocalUser -Name Guest -ErrorAction SilentlyContinue
$results.GuestDisabled = $null -eq $guest -or -not $guest.Enabled

$reportDirectory = 'C:\ImageBuild'
New-Item -ItemType Directory -Path $reportDirectory -Force | Out-Null

$results |
ConvertTo-Json -Depth 4 |
Set-Content "$reportDirectory\validation-report.json"

$failed = $results.GetEnumerator() |
Where-Object {
$_.Key -notin 'TimestampUtc', 'Architecture' -and
$_.Value -ne $true
}

if ($failed) {
$failed | Format-Table -AutoSize | Out-String | Write-Error
throw 'Golden-image validation failed.'
}

Write-Host 'All golden-image validation tests passed.'

Step 10: Sysprep
Example `scripts/90-sysprep.ps1`:
PowerShell
$ErrorActionPreference = 'Stop'

$sysprep = Join-Path $env:WINDIR 'System32\Sysprep\Sysprep.exe'

if (-not (Test-Path $sysprep)) {
throw "Sysprep was not found: $sysprep"
}

Start-Process `
-FilePath $sysprep `
-ArgumentList '/oobe /generalize /shutdown /quiet' `
-Wait

exit 0
Show more lines
Microsoft says generalising removes machine-specific information, including the SID, and prepares the image for reuse. It also warns that updating or installing Microsoft Store apps for individual users can prevent Sysprep from succeeding. [learn.microsoft.com]
For the demo:

-   do not domain-join the image;
-   do not activate it permanently;
-   avoid interacting with Microsoft Store applications;
-   run Sysprep only at the end;
-   never boot the master image after successful generalisation;
-   always boot a copied disk when validating deployment.

Important VMware caveat
A VMDK is not automatically a VMware template.
A usable VMware template normally includes:

-   a compatible VMDK;
-   VM hardware definition;
-   appropriate ARM64 guest type;
-   supported firmware;
-   virtual TPM requirements;
-   compatible virtual devices;
-   import or registration into the actual VMware platform;
-   successful first-boot validation.

Broadcom states that ARM64 guests require UEFI firmware in Fusion on Apple Silicon and identifies NVMe as the recommended storage device and `vmxnet3` as the recommended network adapter. [knowledge....oadcom.com]
More importantly, Broadcom’s ESXi-Arm response says Windows 11 ARM guest customisation is not currently supported on ESXi Arm. Therefore, do not present the converted VMDK as a validated vSphere production template unless you have tested it on the precise target VMware ARM platform. [community....oadcom.com]
For the demo, call it:

> VMware-format VMDK candidate

not:

> production VMware template

Step 13: The true ISO creation path
To produce a customised Windows installation ISO, the flow changes:
Plain Text
Packer-built reference VM
↓
Sysprep /generalize /shutdown
↓
Boot Windows PE
↓
DISM /Capture-Image
↓
Custom install.wim
↓
Replace install.wim in copied ISO tree
↓
Create bootable ARM64 ISO
Show more lines
Conceptually, the capture command inside Windows PE is:
PowerShell
dism /Capture-Image `
/ImageFile:D:\sources\install.wim `
/CaptureDir:C:\ `
/Name:"Windows 11 ARM64 Golden 1.0.0" `
/Compress:max `
/CheckIntegrity `
/Verify
Show more lines
You would then reconstruct installation media containing the captured `install.wim`.
This is where your all-Linux host becomes awkward. Microsoft’s supported Windows deployment tooling, including Windows PE and the Windows ADK workflow, is designed to run in Windows. While Linux ISO tools can author an ISO filesystem, assuming that this alone produces correctly bootable and supportable Windows ARM64 media would be unsafe.
For a reliable demonstration, I recommend:
Plain Text
Phase 1 on Asahi:
Packer → QEMU → QCOW2 → validation → Sysprep → VMDK candidate

Phase 2 in a Windows build worker:
Boot WinPE → DISM capture → install.wim → mastered Windows ARM64 ISO

What will leave the strongest impression
Do not spend the demo clicking through Windows Setup. Focus the audience on six proof points:
1. Repeatability
Delete the output and rebuild it from the same source.
2. Modularity
Remove one script from the pipeline and show how the image profile changes without altering the builder.
3. Policy as code
Show the policy registry values in source control, and then prove them inside the built VM.
4. Controlled failure
Deliberately introduce one incorrect expected value and show the validation gate block release.
5. Identity generalisation
Explain Sysprep, clone the image, and show that the deployed clone enters OOBE rather than retaining the build machine’s identity.
6. Release evidence
End on the artifact directory:
Plain Text
Image
VMware-format candidate
Validation evidence
Manifest
Checksums
Image version
Source checksum
Show more lines
Your best closing sentence would be:

> “This is not a manually maintained Windows build. The image, policy, software, validation, generalisation and release evidence are all generated consistently from version-controlled code.”

That will land substantially better with your audience than presenting Packer as an ISO-editing utility.
